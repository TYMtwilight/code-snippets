BigDecimal - 高精度な10進数計算

  • 📅 作成日: 2026-01-29
  • 🔄 更新日: 2026-10-04

🎯概要

金融計算や精密な10進数演算に使うJavaの数値型。double などの浮動小数点数で起きる丸め誤差を避けて、10進数のまま正確に計算できる。

🔍 用語ノート: スケール(scale)

BigDecimal が持つ「小数点以下の桁数」のこと。new BigDecimal("100.00") のスケールは2、new BigDecimal("100") のスケールは0になる。数値としては同じでも、スケールが違うと別の値として扱われる場面がある(→ 4. 比較する)。

📌使用場面

  • 金額計算(消費税、割引、合計金額など)
  • 科学技術計算で精度が必要な場合
  • 浮動小数点の丸め誤差を許容できない計算

💻コード

1. なぜ BigDecimal を使うのか

// double の丸め誤差
double d1 = 0.1 + 0.2;
System.out.println(d1);  // 0.30000000000000004

// BigDecimal なら正確
BigDecimal b1 = new BigDecimal("0.1").add(new BigDecimal("0.2"));
System.out.println(b1);  // 0.3

✕ double で 0.1 + 0.2

0.30000000000000004

わずかにずれる

✓ BigDecimal で 0.1 + 0.2

0.3

正確に計算できる

double は数値を2進数で持つため、0.1 のような10進数の小数をぴったり表せない。金額の計算でこのずれが積み重なると、合計が1円合わないといった問題になる。

2. 生成する

✓ 推奨
import java.math.BigDecimal;

// 文字列から生成(推奨)
BigDecimal price = new BigDecimal("1000.50");

// 整数から生成
BigDecimal quantity = BigDecimal.valueOf(3);

// double を使う場合は valueOf を使う
BigDecimal good = BigDecimal.valueOf(0.1);  // 0.1
✕ NG
// double から new で直接生成すると、誤差がそのまま入る
BigDecimal bad = new BigDecimal(0.1);  // 0.1000000000000000055511151231...
  • new BigDecimal(0.1) は、0.1 という double が内部で持っている「ずれた値」を、そのまま正確に写し取ってしまう
  • 文字列 "0.1" から作れば、最初から10進数の 0.1 として扱える。double の値しか手元にない場合は BigDecimal.valueOf(0.1) を使う

3. 四則演算

import java.math.RoundingMode;

BigDecimal a = new BigDecimal("100");
BigDecimal b = new BigDecimal("3");

BigDecimal sum      = a.add(b);       // 加算: 103
BigDecimal diff     = a.subtract(b);  // 減算: 97
BigDecimal product  = a.multiply(b);  // 乗算: 300

// 除算: 小数点以下の桁数(スケール)と丸めモードを指定する
BigDecimal quotient = a.divide(b, 2, RoundingMode.HALF_UP);  // 33.33
  • + や - などの演算子は使えない。add / subtract / multiply / divide のメソッドで計算する

⚠️ 除算では丸めモードを指定する

100 ÷ 3 = 33.333… のように割り切れない計算で、桁数と丸めモードを指定せずに a.divide(b) と書くと、ArithmeticException が発生する。結果をどこで丸めるか決められないため。

⚠️ 計算結果は戻り値で受け取る(イミュータブル)

BigDecimal はイミュータブル(作ったあとに値を変えられない)。a.add(b) を呼んでも a 自体は変わらず、結果は新しいオブジェクトとして返される。a.add(b); とだけ書いて戻り値を受け取らないと、計算結果が捨てられてしまう。

4. 比較する

BigDecimal x = new BigDecimal("100.00");
BigDecimal y = new BigDecimal("100");

// equals: スケールも比較する(100.00 と 100 は別物)
x.equals(y);     // false

// compareTo: 数値として比較する(100.00 と 100 は同じ)
x.compareTo(y);  // 0(等しい)

new BigDecimal("50").compareTo(new BigDecimal("100"));  // -1(小さい)
メソッド100.00 と 100比べるもの
equalsfalse数値とスケールの両方
compareTo0(等しい)数値だけ

compareTo の戻り値は、負の数なら「小さい」、0 なら「等しい」、正の数なら「大きい」。金額が同じかどうかを判定したいときは、equals ではなく compareTo(...) == 0 を使う。

5. 丸める

BigDecimal value = new BigDecimal("123.456");

// 小数点以下2桁に丸める(四捨五入)
BigDecimal rounded = value.setScale(2, RoundingMode.HALF_UP);  // 123.46

setScale(桁数, 丸めモード) で、小数点以下を何桁にするかと、どう丸めるかを指定する。主な丸めモードは次のとおり(小数点以下0桁に丸めた場合)。

丸めモード意味2.5-2.5
HALF_UP四捨五入3-3
HALF_DOWN五捨六入2-2
CEILING正の無限大方向へ3-2
FLOOR負の無限大方向へ2-3
DOWNゼロ方向へ(切り捨て)2-2
UPゼロから離れる方向へ(切り上げ)3-3

6. よく使う定数

BigDecimal zero = BigDecimal.ZERO;  // 0
BigDecimal one  = BigDecimal.ONE;   // 1
BigDecimal ten  = BigDecimal.TEN;   // 10

合計金額を 0 から足し上げるときの初期値などに使う。毎回 new BigDecimal("0") と書かなくて済む。

7. 実用例: 消費税計算

public static BigDecimal calculateTax(BigDecimal price, BigDecimal taxRate) {
    // 税額 = 価格 × 税率 → 1円未満は切り捨て
    return price.multiply(taxRate).setScale(0, RoundingMode.DOWN);
}

public static BigDecimal calculateTotalWithTax(BigDecimal price) {
    BigDecimal taxRate = new BigDecimal("0.10");  // 10%
    BigDecimal tax = calculateTax(price, taxRate);
    return price.add(tax);
}

例: price が 1234 の場合

  • 税額: 1234 × 0.10 = 123.40 → 1円未満を切り捨てて 123
  • 税込み金額: 1234 + 123 = 1357

税率も文字列 "0.10" から作っているので、計算の途中で誤差が入らない。

8. まとめ: 4つのルール

  1. 文字列から生成するnew BigDecimal("0.1") を使う。double のリテラルから new しない
  2. 除算では丸めモードを指定する指定しないと、割り切れないときに ArithmeticException が発生する
  3. 比較は compareTo を使うequals はスケールも比べるので、100.00 と 100 が別物になる
  4. 計算結果は戻り値で受け取るイミュータブルなので、演算結果は新しいオブジェクトとして返される
