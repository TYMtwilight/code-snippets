List と Iterable の違い

  • 📅 作成日: 2026-03-01
  • 🔄 更新日: 2026-10-05

🎯概要

Java における Iterable<T> と List<T> の継承関係・機能差・使い分けをまとめる。

🔍 用語ノート: Iterable

iterator() メソッドだけを持つ最小限のインターフェース。これを実装していれば for-each ループで回せる。 「回せること」しか保証しないため、DB の検索結果やファイルなど、一方向に流れるデータの型としても使われる。

📌使用場面

  • メソッドの引数・戻り値の型を決めるとき
  • Spring Data の CrudRepository.findAll() の戻り値を扱うとき

💻コード

1. 継承関係

// Iterable<T>
//   └── Collection<T>
//         └── List<T>
//               └── ArrayList, LinkedList, ...

List は Iterable の子孫なので、List は常に Iterable として扱える。逆（Iterable → List）は変換が必要。

2. Iterable: for-each ループで回せることだけを保証

Iterable<Item> iterable = itemRepository.findAll(); // CrudRepository の戻り値
for (Item item : iterable) {
    System.out.println(item);
}

Iterable でできるのは基本的に「順番に取り出すこと」だけ。get() や size() は使えない。

3. List: 豊富な操作が使える

List<Item> list = new ArrayList<>();
list.get(0);        // インデックスアクセス ✅
list.size();        // サイズ取得 ✅
list.add(item);     // 追加 ✅
list.remove(0);     // 削除 ✅

4. Iterable → List への変換

// 方法1: forEach でひとつずつ追加
List<Item> list1 = new ArrayList<>();
iterable.forEach(list1::add);

// 方法2: StreamSupport を使う
List<Item> list2 = StreamSupport
    .stream(iterable.spliterator(), false)
    .collect(Collectors.toList());

各要素の意味

  • メソッド参照 list1::add

    item -> list1.add(item) の省略形。要素を1つずつ list1 に追加する。

  • Stream への変換 StreamSupport.stream(spliterator, parallel)

    Iterable には stream() メソッドがないため、spliterator() を経由して Stream を作る。第2引数 false は「並列ではなく順次処理」の指定。

    補足
    Java 16 以降は .collect(Collectors.toList()) の代わりに .toList() も使える（ただし戻り値は変更不可の List）。

5. 比較と使い分け

操作IterableList
for-each✅✅
インデックスアクセス❌✅
size()❌✅
add() / remove()❌✅
用途「回せる」最低限保証順序付きコレクション
  • Iterable は iterator() メソッドのみを持つ最小限のインターフェース。DB やファイルなど一方向に流れるデータに使われる。
  • List はランダムアクセス・サイズ取得・追加・削除など豊富な操作を提供する。
  • 使い分け: for-each だけなら引数・戻り値を Iterable にすると呼び出し側の柔軟性が上がる。インデックス操作や追加・削除が必要なら List を使う。
