PostgreSQLドライバとapplication.propertiesの関係

  • 📅 作成日: 2026-09-21
  • 🔄 更新日: 2026-09-21

🎯概要

PostgreSQLに接続するには、postgresqlドライバ(pom.xml)と接続設定(application.properties)の2つが必要になる。それぞれが何の役割を持ち、どう組み合わさって接続が成立するのかを整理する。

🔍 用語ノート: runtimeスコープとは

Mavenの依存関係が「いつ必要になるか」を指定する設定の1つ。依存関係(ライブラリ)は、大きく分けて2つのタイミングで使われる。

・コンパイル時: コードを書くときに、そのクラスやインターフェースをimportして直接参照する
・実行時: アプリを動かすときに、裏側で実際に必要になる

Mavenの<scope>は、この「どのタイミングで必要か」をMavenに伝えるための指定。 

<dependency>
    <groupId>org.postgresql</groupId>
    <artifactId>postgresql</artifactId>
    <scope>runtime</scope>
</dependency>
スコープコンパイル時実行時例
compile(デフォルト)必要必要Spring MVCなど、コードで直接使うもの
runtime不要必要JDBCドライバなど
testテストのみテストのみJUnitなど
provided必要不要(サーバー側が用意)Servlet APIなど

💻コード

1. pom.xmlへの追加

<dependency>
    <groupId>org.postgresql</groupId>
    <artifactId>postgresql</artifactId>
    <scope>runtime</scope>
</dependency>

なぜruntimeスコープなのか

普段書くコードの中にorg.postgresql.Driverは出てこない。触るのはJpaRepositoryやEntityManagerといったJPA(Hibernate)側のAPIだけで、ドライバのクラスを直接importすることはない。

// これは書くが…
userRepository.findById(1L);

// こういうのは書かない
// org.postgresql.Driver driver = new org.postgresql.Driver();

とはいえドライバが不要というわけではない。JPA(Hibernate)がPostgreSQLと実際に通信する瞬間には、「PostgreSQLの言葉に翻訳してくれる相手」としてこのドライバが裏側で動いている。

  • コンパイル時は不要: コードがドライバのクラスを直接参照していないため
  • 実行時は必要: JPA/HibernateがDBに接続する瞬間に、裏側で呼び出されるため

つまりruntimeスコープとは、「コードには出てこないが、実行時には必要になるもの」に付ける指定。

2. application.propertiesへの追加

spring.datasource.url=jdbc:postgresql://localhost:5432/mydb
spring.datasource.username=postgres
spring.datasource.password=secret

# 任意: Hibernateがテーブルを自動生成/検証する挙動
spring.jpa.hibernate.ddl-auto=update

ドライバと設定、両方が必要な理由

結論としては、ドライバと設定はセットで機能するもので、どちらか片方だけでは接続できない。役割分担は次の通り。

  • postgresqlドライバ(runtimeスコープ): PostgreSQLと実際に通信する「翻訳者」そのもの。JDBCの標準的な呼び出しを、PostgreSQL固有の通信プロトコルに変換する実体(コード)
  • application.propertiesの設定: その翻訳者に対する「接続先の指示書」。どこ(url)に、誰の名前で(username)、どうやって(password)接続するかという情報

Spring Bootが起動すると、内部で(自動設定によって)だいたい次のような処理が行われる。

// イメージ(実際にはSpring Bootが自動でやる)
DataSource dataSource = DriverManager.getConnection(
    "jdbc:postgresql://localhost:5432/mydb",  // ← application.propertiesのurl
    "postgres",                                // ← username
    "secret"                                   // ← password
);

このときjdbc:postgresql://...というURLを見て、「これはPostgreSQL用の接続だ」と判断し、クラスパス上にあるorg.postgresql.Driver(＝runtimeスコープで追加した依存関係)を実際に呼び出す。

  • ドライバだけあって設定がない → どこに接続すればいいか分からず起動できない
  • 設定だけあってドライバがない → 接続先は分かっているが、PostgreSQLと会話する手段(通信ロジック)がクラスパス上に存在せず、起動時にClassNotFoundExceptionのようなエラーになる

application.propertiesは「runtimeスコープの依存関係を使うために必須の設定」というより、「その依存関係(ドライバ)にどう動いてほしいかを教える設定」。どちらか一方だけでは接続できず、両方揃って初めてデータベース接続が成立する。

🔍 補足: Configクラスは必要か

基本的に自分で書く必要はない。spring-boot-starter-data-jpa + postgresqlドライバがクラスパスにあれば、Spring Bootの自動設定(Auto Configuration)がDataSourceやEntityManagerFactory、TransactionManagerなどを自動的に組み立ててくれる。最低限必要なのは前述のapplication.propertiesの接続情報だけ。

これだけで、Spring Bootが裏側で以下を自動的に行う。

  • postgresqlドライバがクラスパスにあることを検出
  • DataSource(コネクションプール、デフォルトはHikariCP)を自動生成
  • JPA用のEntityManagerFactoryを自動生成
  • PlatformTransactionManagerを自動生成

明示的なConfigクラス(@Configuration)が必要になるケース
・複数のデータベースに接続したい(マルチDataSource)
・コネクションプールの詳細設定を細かくカスタマイズしたい
・DataSourceの生成方法自体を独自にしたい(特殊な認証方式など)

単一のPostgreSQLに接続するだけの一般的なアプリであれば、application.propertiesの数行だけで十分。
