Spring Initializrでのプロジェクト作成

  • 📅 作成日: 2026-09-21
  • 🔄 更新日: 2026-09-21

🎯概要

Spring Initializr(start.spring.io)を使ってSpring Bootプロジェクトの雛形を生成する方法と、REST API開発でまず選ぶべき依存関係(Web, JPA, Validation, PostgreSQL Driver等)の意味を整理する。

迷ったら「最初は最小限、後から pom.xml に追記」で問題ない。依存関係の追加自体はいつでもできる。

🔍 用語ノート: 依存関係(スターター)とは

Spring Bootでは、特定の機能を使うために必要な複数のライブラリを1つにまとめた「スターター(starter)」という依存関係が用意されている。名前はspring-boot-starter-〇〇という形式で、例えばspring-boot-starter-webならWeb開発に必要なライブラリ一式(Spring MVC、組み込みTomcatなど)がまとめて入っている。「依存関係」と「スターター」はほぼ同じ意味で使われることが多く、このページでも「依存関係(スターター)」という書き方で両方を指す。

「バージョンを揃える」と「自動設定」は別の話
スターターを追加すると2つのことが起きるが、混同しやすいので分けて整理する。

・バージョンの管理: スターター自体にバージョン番号は書かれておらず、Spring Bootの親(spring-boot-starter-parent)が各ライブラリの互換性が取れたバージョンを一括管理している。
・自動設定(Auto Configuration): アプリ起動時に、クラスパス上のライブラリを見てSpring Bootが必要なBean(DataSourceなど)を自動的に生成・登録する仕組み。本来自分で@Configurationクラスに書くべき設定を、Spring Bootが代わりに行ってくれる。

つまり「バージョンが揃う」のは前提条件、その上で「実行時にBeanを自動的に組み立てる」のが自動設定、という2段階の話になっている。

📌使用場面

  • 新しくSpring Bootプロジェクトを立ち上げるとき
  • 依存関係(スターター)の選び方で迷ったとき
  • 既存プロジェクトに新しい機能(DBアクセス、バリデーション等)を追加する前に、必要なスターターを確認したいとき

🔍 既存プロジェクトでの使い方

Spring Initializrは「新しいプロジェクトを作るときだけ」使うツールと思われがちだが、既に動いている既存プロジェクトに機能を後から追加したい場合にも参考になる。例えば「DBアクセス機能を追加したい」となった場合、実際に必要なのは新しいプロジェクトを作ることではなく、pom.xmlに依存関係(スターター)を1つ追記することだけ。 

<!-- DBアクセスを追加したいなら -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-jpa</artifactId>
</dependency>

<!-- バリデーションを追加したいなら -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-validation</artifactId>
</dependency>

ただartifactIdを正確に思い出せるとは限らない。そういうとき、start.spring.ioの画面を開いて依存関係を探すと、正式なartifactId名や関連する他のスターターも一覧で確認できる。実際にプロジェクトを生成・ダウンロードしなくても、依存関係の名前を確認する目的だけで画面を使ってよい。

💻コード

1. curlコマンドでプロジェクトを取得する

# Spring InitializrのAPIを直接叩いてzipを取得することもできる
curl https://start.spring.io/starter.zip \
  -d type=maven-project \
  -d language=java \
  -d bootVersion=3.3.0 \
  -d javaVersion=17 \
  -d groupId=com.example \
  -d artifactId=snippet-review-app \
  -d dependencies=web,data-jpa,postgresql,validation \
  -o snippet-review-app.zip

curlはコマンドラインからHTTPリクエストなどを送るツール。URLを指定するだけでGETリクエストを送れ、オプションを付けることでPOSTリクエスト送信やファイル保存など、ブラウザでできることの多くをコマンド一発で再現できる。

使用しているオプション

  • -d (--data): POSTリクエストのボディにデータを追加する。1つでも付けると自動的にPOSTリクエストになり、複数回指定すると&で連結されて1つのフォームデータとして送信される(type=maven-project&language=java&...)。start.spring.ioの画面でポチポチ設定してDownloadを押すのと同じことをコマンド1つで行っている。
  • -o (--output): レスポンス(zipファイル)を標準出力ではなく、指定したファイル名で保存する。

実際に送信されるPOSTリクエスト(イメージ)

上のcurlコマンドは、実際には次のようなHTTPリクエストを送っているのと同じ。

POST /starter.zip HTTP/1.1
Host: start.spring.io
Content-Type: application/x-www-form-urlencoded

type=maven-project&language=java&bootVersion=3.3.0&javaVersion=17&groupId=com.example&artifactId=snippet-review-app&dependencies=web,data-jpa,postgresql,validation

複数指定した-dの値が&で連結され、1本のフォームデータ(Content-Type: application/x-www-form-urlencoded)としてリクエストボディにまとめられている。

2. 生成される pom.xml と依存関係

pom.xml の依存関係部分(抜粋)

<dependencies>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-data-jpa</artifactId>
    </dependency>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-validation</artifactId>
    </dependency>
    <dependency>
        <groupId>org.postgresql</groupId>
        <artifactId>postgresql</artifactId>
        <scope>runtime</scope>
    </dependency>
</dependencies>

各依存関係の意味

  • Web spring-boot-starter-web

    Spring MVCと組み込みTomcatを追加し、@RestControllerなどでHTTPエンドポイントを作れるようにする。これが無いとREST APIの土台自体がない。

    組み込みTomcatとは
    従来はTomcat(サーバー)を別途インストールし、その中に自分のアプリ(.war)を配置して動かす必要があった。Spring Bootでは主従が逆転し、自分のアプリのjarファイルの中にTomcat本体がライブラリとして同梱される。そのため、アプリを実行するだけで、Tomcatが勝手に内部で起動し、すぐブラウザからアクセスできる状態になる。

  • JPA (Spring Data JPA) spring-boot-starter-data-jpa

    Hibernateをベースに、Entityとリポジトリインターフェースだけで基本的なCRUDを実装できるようにする。SQLを直接書かずに済む範囲が広がる。

    🔍 深掘り: HibernateとJPAの関係

    ① Hibernateとは

    Javaのオブジェクト(クラス)とデータベースのテーブルを自動的に対応づけてくれるライブラリ(ORM = Object-Relational Mapping、の代表的な実装)。

    本来、データベースを扱うには自分でSQLを書く必要がある。

    SELECT * FROM users WHERE id = 1;

    これをJavaでやろうとすると、SQL文字列を組み立てて、結果セットを1行ずつ読み取ってオブジェクトに詰め替える…といった面倒な作業が発生する。Hibernateを使うと、代わりにこう書ける。

    User user = entityManager.find(User.class, 1L);

    UserというJavaクラス(Entity)を1件取得しているだけだが、裏側でHibernateが自動的にSQLを組み立てて実行し、結果をJavaオブジェクトに変換してくれている。

    データベース側Javaオブジェクト側
    usersテーブルUserクラス
    テーブルの1行(レコード)Userのインスタンス1つ
    カラム(name, email)フィールド(name, email)

    この対応づけをHibernateが自動でやってくれるので、SQLを直接書かなくても、Javaのオブジェクトを操作する感覚でデータベースのCRUD(作成・取得・更新・削除)ができる。

    ② JPA・Hibernate・Spring Data JPAの関係

    ・JPA: 「JavaでORMをやる際のルール(仕様・インターフェース)」を定めたもの
    ・Hibernate: そのJPAというルールを実際に実装したライブラリ(実装は他にもあるが、Hibernateが事実上の標準)
    ・Spring Data JPA: JPA(=Hibernate)をさらに使いやすくラップし、リポジトリインターフェースを定義するだけでCRUDメソッドが自動生成される仕組み

    「ラップする」とはどういうことか
    JPA(Hibernate)を直接使う場合、Hibernateが提供するEntityManagerというAPIを自分で操作する必要がある。 

    // 1件取得
User user = entityManager.find(User.class, 1L);

// 条件検索(JPQLというSQLに似たクエリ言語を書く)
List<User> users = entityManager.createQuery(
    "SELECT u FROM User u WHERE u.name = :name", User.class)
    .setParameter("name", "Taro")
    .getResultList();

// 保存
entityManager.persist(user);

    一方Spring Data JPAを使う場合、インターフェースを1つ定義するだけで、同等のことができるようになる。

    public interface UserRepository extends JpaRepository<User, Long> {
    List<User> findByName(String name);
}
    // 1件取得
User user = userRepository.findById(1L).get();

// 条件検索(メソッド名から自動でクエリが作られる)
List<User> users = userRepository.findByName("Taro");

// 保存
userRepository.save(user);

    Spring Data JPAは、内部では結局Hibernate(＝JPAの実装)のEntityManagerを呼び出している。ただし、その面倒な呼び出しコードをSpring Data JPA側が肩代わりして隠してくれているため、開発者はEntityManagerを直接触らずに済む。

    「ラップ(wrap) = 包む」とは、中身(EntityManager、JPQL)を直接触らせず、外側からシンプルなインターフェース(findById、findByNameなど)だけを提供する、という意味。Hibernate(JPA)という複雑なものの外側に、Spring Data JPAというシンプルな殻をかぶせて使いやすくしている、とイメージするとよい。

    つまり「Spring Data JPA(リポジトリ機能) → JPA(仕様) → Hibernate(実装)」という重なりになっている。

    ③ spring-boot-starter-data-jpaを追加しないとHibernateも入らないのか

    その通り。spring-boot-starter-data-jpaを追加しないと、Hibernateはクラスパスに入らない。

    spring-boot-starter-data-jpa自体は処理を持っているわけではなく、「JPA関連のライブラリを一式まとめて引っ張ってくる」ためのスターター(依存関係の詰め合わせ)。②の3層(Spring Data JPA / JPA仕様 / Hibernate)は、実際にはこのスターター1つの中に依存関係としてまとめて入っている。Mavenの依存関係ツリーを見ると、各層が次のように対応している。 

    spring-boot-starter-data-jpa
 ├─ spring-data-jpa       ← ②の「Spring Data JPA」(リポジトリ機能)
 ├─ hibernate-core        ← ②の「Hibernate」(JPA仕様の実装本体)
 ├─ spring-orm
 └─ ...

    つまりspring-boot-starter-data-jpaをpom.xmlに1行追加するだけで、Hibernateを含む一連のJPA関連ライブラリがまとめてクラスパスに入る仕組み。逆にこれを追加しなければ、Hibernateはプロジェクトに存在せず、EntityManagerや@EntityといったJPA関連の機能も一切使えない。

    補足
    ・依存関係を個別にhibernate-coreだけ追加することも技術上は可能だが、バージョンの整合性(Spring Bootとの互換性)を自分で管理する必要があり、通常はスターター経由で導入するのが推奨される
    ・Hibernate以外のJPA実装(EclipseLinkなど)に差し替えることも可能だが、その場合はスターターからHibernateを除外し、別途設定が必要になる

  • Validation spring-boot-starter-validation

    @Validや@NotNull、@SizeなどのBean Validationアノテーションが使えるようになる。リクエストDTOの入力チェックに必須。

  • PostgreSQL Driver postgresql

    JDBC経由でPostgreSQLに接続するためのドライバ。runtimeスコープなのでコンパイル時には直接使わない。

    runtimeスコープの意味、application.propertiesとの役割分担、Configクラスが必要になるケースなどの詳細は別ページにまとめた。
