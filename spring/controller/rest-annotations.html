RESTコントローラーの主要アノテーション

  • 📅 作成日: 2026-09-21
  • 🔄 更新日: 2026-10-03

🎯概要

@RestControllerを中心に、パスの切り方(@RequestMapping)、HTTPメソッドの振り分け(@GetMapping/@PostMapping)、パラメータの受け取り方(@PathVariable/@RequestParam/@RequestBody)の役割分担を整理する。

@RestController

@Controller + @ResponseBody の合成。戻り値を自動的にJSONへシリアライズしてレスポンスボディに書き込む。画面(View)を返さないAPI専用コントローラーであることを明示する。

@RestController
public class ProductController { ... }

@RequestMapping("/api/products")

クラスに付けることで、そのコントローラー内の全エンドポイントに共通のベースパスを設定する。

@RequestMapping("/api/products")
public class ProductController { ... }

@GetMapping / @PostMapping

@RequestMapping(method = ...)の短縮形。HTTPメソッドごとにハンドラメソッドを分ける。

@GetMapping("/{id}")
public ResponseEntity<ProductResponse> getById(...) { ... }

@PostMapping
public ResponseEntity<ProductResponse> create(...) { ... }

@PathVariable

URLパスの一部(/products/42の42)を受け取る。リソースを一意に識別するIDなど、「そのURL自体の一部」を表す値に使う。

// GET /api/products/42
@GetMapping("/{id}")
public ResponseEntity<ProductResponse> getById(@PathVariable Long id) {
    return ResponseEntity.ok(productService.findById(id));
}

@RequestParam

クエリパラメータ(?category=book&page=0)を受け取る。検索条件・フィルタ・ページングなど、任意/省略可能な値に使うことが多い。

// GET /api/products?category=book&page=0
@GetMapping
public ResponseEntity<List<ProductResponse>> search(
        @RequestParam(required = false) String category,
        @RequestParam(defaultValue = "0") int page) {
    return ResponseEntity.ok(productService.search(category, page));
}

Formクラスでまとめて受け取る

クエリパラメータが多いときは、1つずつ @RequestParam で受けるかわりに、パラメータをまとめたクラス（Formクラス）で受け取れる。パラメータ名と同じ名前のフィールドに、Springが値を入れてくれる。

ProductSearchForm.java
@Data
public class ProductSearchForm {
    private String category;     // 指定がなければ null
    private String keyword;      // 指定がなければ null
    private Integer page = 0;    // 指定がなければ 0
}
ProductController.java
// GET /api/products?category=book&keyword=java&page=0
@GetMapping
public ResponseEntity<List<ProductResponse>> search(ProductSearchForm form) {
    return ResponseEntity.ok(productService.search(form));
}

🏷️ アノテーションは付けない

引数がFormクラスのようなオブジェクトなら、Springが自動的に @ModelAttribute として扱う。次の2つは同じ意味になる。

search(ProductSearchForm form) ＝ search(@ModelAttribute ProductSearchForm form)

⚠️ @RequestBody を付けると、クエリパラメータではなくリクエストボディのJSONを読みにいってしまう。

🔢 省略されたパラメータは初期値のまま

送られてこなかったパラメータのフィールドには値が入らない。@RequestParam の defaultValue のかわりに、フィールドに初期値を書いておく。

リクエストcategorykeywordpage
?category=book"book"null0（初期値）
?category=book&page=2"book"null2

⚖️ @RequestParam との使い分け

パラメータが1〜2個

→ @RequestParam

必須・デフォルト値もアノテーションだけで指定できる

パラメータが多い・今後増えそう

→ Formクラス

Controllerの引数が1つで済み、Serviceにもそのまま渡せる

@RequestBody

リクエストボディのJSONを、Jacksonを介してJavaオブジェクト(DTO)に変換する。作成・更新系のPOST/PUTでよく使う。

// POST /api/products
@PostMapping
public ResponseEntity<ProductResponse> create(@Valid @RequestBody ProductCreateRequest request) {
    ProductResponse created = productService.create(request);
    return ResponseEntity.status(HttpStatus.CREATED).body(created);
}

💡 使い分けの目安

そのリソースを特定するためのIDか?

→@PathVariable

GET /api/products/42

絞り込み・並び替え・省略可能なオプションか?

→@RequestParam（数が多ければFormクラス）

GET /api/products?category=book&page=0

作成・更新するデータ本体か?

→@RequestBody

POST /api/products
Body: { "name": "...", "price": 1200 }

💻コード

@RestController
@RequestMapping("/api/products")
public class ProductController {

    private final ProductService productService;

    public ProductController(ProductService productService) {
        this.productService = productService;
    }

    @GetMapping("/{id}")
    public ResponseEntity<ProductResponse> getById(@PathVariable Long id) {
        return ResponseEntity.ok(productService.findById(id));
    }

    @GetMapping
    public ResponseEntity<List<ProductResponse>> search(
            @RequestParam(required = false) String category,
            @RequestParam(defaultValue = "0") int page) {
        return ResponseEntity.ok(productService.search(category, page));
    }

    @PostMapping
    public ResponseEntity<ProductResponse> create(@Valid @RequestBody ProductCreateRequest request) {
        ProductResponse created = productService.create(request);
        return ResponseEntity.status(HttpStatus.CREATED).body(created);
    }
}

コード解説

  1. @RestController
@RequestMapping("/api/products")
public class ProductController {

    @RestControllerでこのクラスをREST用のコントローラーとして登録し、各メソッドの戻り値をJSONとしてレスポンスボディに書き込む。@RequestMapping("/api/products")でクラス全体の共通パスを固定し、以降の各メソッドのパスはこれに追加される形になる。

  2. private final ProductService productService;

public ProductController(ProductService productService) {
    this.productService = productService;
}

    ビジネスロジックを担うProductServiceをフィールドとして保持し、コンストラクタインジェクションでSpringに注入してもらう。

  3. @GetMapping("/{id}")
public ResponseEntity<ProductResponse> getById(@PathVariable Long id) {
    return ResponseEntity.ok(productService.findById(id));
}

    GET /api/products/{id}宛のリクエストを割り当てる。URLパスの{id}部分を@PathVariableでLong idとして受け取り、取得したデータをステータス200(OK)とともに返す。

  4. @GetMapping
public ResponseEntity<List<ProductResponse>> search(
        @RequestParam(required = false) String category,
        @RequestParam(defaultValue = "0") int page) {
    return ResponseEntity.ok(productService.search(category, page));
}

    GET /api/products（パスの後ろに何も付かない）へのリクエストを受け取る、検索用のメソッド。クエリパラメータは2つとも省略できる。

    • ?category=...: required = false なので、省略すると null
    • ?page=...: defaultValue = "0" なので、省略すると 0

    検索結果は一覧（List）にして、200 OK で返す。

  5. @PostMapping
public ResponseEntity<ProductResponse> create(@Valid @RequestBody ProductCreateRequest request) {
    ProductResponse created = productService.create(request);
    return ResponseEntity.status(HttpStatus.CREATED).body(created);
}

    POST /api/products へのリクエストを受け取る、新規作成用のメソッド。次の順番で処理が進む。

    1. @RequestBody: リクエストボディのJSONを ProductCreateRequest に変換する
    2. @Valid: 中身が入力ルールに合っているかチェックする（合っていなければ、ここで 400 Bad Request）
    3. productService.create(request): 登録処理は Service に任せる
    4. 作成した商品を、201 Created で返す
