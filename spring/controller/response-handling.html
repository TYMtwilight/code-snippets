レスポンスの返し方とエラーハンドリング

  • 📅 作成日: 2026-09-21
  • 🔄 更新日: 2026-09-21

🎯概要

ResponseEntity<T>を使ってステータスコードを明示的に返す方法と、@ControllerAdvice + @ExceptionHandlerによる例外処理の共通化を、MVPレベルの最小構成で整理する。

📌使用場面

  • 200 OK / 201 Created / 404 Not Foundなどを状況に応じて正しく返したいとき
  • 「見つからない場合」「入力値が不正な場合」などの例外処理を、各コントローラーに個別に書かず一箇所に集約したいとき
  • まずは最低限のエラーハンドリングだけ実装し、後から拡充したいとき

💻コード

// --- コントローラー: ステータスコードを明示する ---
@RestController
@RequestMapping("/api/snippets")
public class SnippetController {

    private final SnippetService snippetService;

    public SnippetController(SnippetService snippetService) {
        this.snippetService = snippetService;
    }

    @GetMapping("/{id}")
    public ResponseEntity<SnippetReviewDto> getById(@PathVariable Long id) {
        SnippetReviewDto dto = snippetService.findById(id); // 見つからなければ例外を投げる
        return ResponseEntity.ok(dto); // 200 OK
    }

    @PostMapping
    public ResponseEntity<SnippetReviewDto> create(@Valid @RequestBody SyncRequestDto request) {
        SnippetReviewDto created = snippetService.create(request);
        return ResponseEntity.status(HttpStatus.CREATED).body(created); // 201 Created
    }
}

// --- 見つからない場合の独自例外 ---
public class SnippetNotFoundException extends RuntimeException {
    public SnippetNotFoundException(Long id) {
        super("Snippet not found: id=" + id);
    }
}

// --- 例外処理を一箇所に集約する ---
@ControllerAdvice
public class GlobalExceptionHandler {

    // 404: リソースが見つからない
    @ExceptionHandler(SnippetNotFoundException.class)
    public ResponseEntity<ErrorResponse> handleNotFound(SnippetNotFoundException ex) {
        ErrorResponse body = new ErrorResponse(ex.getMessage());
        return ResponseEntity.status(HttpStatus.NOT_FOUND).body(body);
    }

    // 400: @Valid によるバリデーションエラー
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ErrorResponse> handleValidation(MethodArgumentNotValidException ex) {
        String message = ex.getBindingResult().getFieldErrors().stream()
                .map(err -> err.getField() + ": " + err.getDefaultMessage())
                .collect(Collectors.joining(", "));
        return ResponseEntity.badRequest().body(new ErrorResponse(message));
    }
}

public record ErrorResponse(String message) {}
  • ResponseEntity<T>: 戻り値の型に直接オブジェクトを書く(public SnippetReviewDto getById(...))だけでも動くが、その場合ステータスコードは常に200固定になる。ResponseEntityで包むことで、作成時は201、未発見時は404など、状況に応じたステータスを明示的に返せる。
  • @ControllerAdvice: アプリ全体(または指定したパッケージ)のコントローラーを横断して例外処理を適用するクラスに付けるアノテーション。個々のコントローラーにtry-catchを書かずに済む。
  • @ExceptionHandler: 特定の例外クラスが投げられたときに実行するメソッドを指定する。複数の例外タイプごとにメソッドを分けて、それぞれ適切なステータスコードとメッセージを返す。
  • MVPでの最低限運用: 最初は「404(見つからない)」と「400(バリデーションエラー)」の2パターンだけ用意すれば十分なことが多い。認証エラーや想定外の例外(500)へのハンドリングは、必要になった時点で@ExceptionHandlerを追加していけばよい。
