ResponseEntity.created() - リソース作成レスポンスの便利メソッド

  • 📅 作成日: 2026-02-14
  • 🔄 更新日: 2026-09-21

🎯概要

REST APIでリソース作成時に 201 Created レスポンスと Location ヘッダーを返す際、Springの ResponseEntity.created() を使って簡潔に記述する方法。

REST設計では「作成に成功したら 200 OK ではなく 201 Created を返し、Location ヘッダーで作成された新しいリソースのURIをクライアントに教える」のが慣習になっている。ResponseEntity.created() はこの2つ（ステータスコード + ヘッダー）をまとめて設定してくれる専用メソッド。

リソース＝データのまとまり、URL＝そのリソースの場所を一意に指し示す住所（例: /cashcards/123）。

📌使用場面

  • @PostMapping でリソースを新規作成し、作成先URIをクライアントに返すとき
  • RESTful APIのベストプラクティスに従った 201 Created レスポンスを返すとき
  • クライアント側が、作成直後にそのリソースへ続けてアクセス（例: 詳細取得やフロントエンドの画面遷移）したいとき

💻コード

// ✅ Spring提供の便利メソッド（推奨）
return ResponseEntity
        .created(uriOfCashCard)
        .build();

// ❌ 手動で全部指定する方法（冗長）
return ResponseEntity
        .status(HttpStatus.CREATED)
        .header(HttpHeaders.LOCATION,
                uriOfCashCard.toASCIIString())
        .build();

実際の使用例

@PostMapping
public ResponseEntity<Void> createCashCard(@RequestBody CashCard newCard) {
    CashCard saved = repository.save(newCard);

    // 作成したリソースのURI: /cashcards/123
    URI location = URI.create("/cashcards/" + saved.getId());

    // 便利メソッドで一発
    return ResponseEntity.created(location).build();
}

レスポンス例

クライアントはレスポンスボディを見なくても、Location ヘッダーの値だけで「どこに何が作られたか」がわかる。

HTTP/1.1 201 Created
Location: /cashcards/123

💡説明

なぜ 200 OK ではなく 201 Created なのか

200 OK は「リクエストが成功した」ことしか表さない汎用的なステータス。一方 201 Created は「新しいリソースがサーバー上に作成された」ことまで明示するので、クライアント（や間に入るキャッシュ・監視ツールなど）が意味を正しく解釈できる。REST APIでは「操作の結果として何が起きたか」をステータスコードで正確に伝えることが重要視される。

なぜ Location ヘッダーが必要なのか

作成したリソースのIDやURLは、サーバー側で採番されることが多く、リクエストを送ったクライアントはあらかじめ知らない。Location ヘッダーにURIを入れて返すことで、クライアントは「作成されたリソースが具体的にどこにあるか」を後続の処理（詳細取得・画面遷移など）にそのまま使える。

created() メソッドが自動で行うこと

  • ステータスコードを 201 Created に設定
  • Location ヘッダーにURIを追加
  • URIの形式チェック（バリデーション）

手動指定に対する利点

  • コードが短い: 1行で済む
  • ミスが減る: ステータスコードやヘッダー名の間違いを防げる（例: HttpHeaders.LOCATION のスペルミスや、ステータスコードの数値取り違え）
  • URI検証: URIが正しい形式かチェックしてくれる
  • 意図が明確: created という名前で何をしているか一目瞭然

使用例のポイント

  • repository.save(newCard) でDBに保存すると、自動採番されたIDを持つエンティティが返ってくる。このIDがあって初めて作成先URIが確定する。
  • URI.create("/cashcards/" + saved.getId()) で、保存後に確定したIDをもとにURIを組み立てている。URI.create() は文字列が不正なURI形式だと IllegalArgumentException を投げるため、単純な文字列連結よりも安全。
  • 戻り値の型が ResponseEntity<Void> になっているのは、レスポンスボディを返さず、ステータスコードと Location ヘッダーだけでクライアントに情報を伝えているため。
