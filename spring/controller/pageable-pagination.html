Pageable - ページネーション・ソート付きの一覧を返す

  • 📅 作成日: 2026-02-14
  • 🔄 更新日: 2026-10-03

🎯概要

@GetMappingとPageableパラメータを組み合わせて、ページネーション・ソート付きのGET一覧エンドポイントを実装するパターン。

📌使用場面

  • REST APIで一覧取得エンドポイントを実装する場合
  • 大量データをページ分割して返却する場合
  • クライアントにソート順を指定させたい場合

例: ECサイトの商品一覧画面。「1ページに20件ずつ表示」「2ページ目へ移動」「価格の安い順に並べ替え」といった操作を、APIのクエリパラメータで受け取る。並べ替えの指定がなければ新着順で表示する。

💻コード

1NG例: CrudRepository.findAll() で全件返す

本番では非推奨
@GetMapping()
private ResponseEntity<Iterable<Product>> findAll() {
   return ResponseEntity.ok(productRepository.findAll());
}
🚫 全件をまとめて返してしまう

件数の上限もソートもないため、商品が増えるほどレスポンスとメモリ使用量が膨らむ。

観点NG例 (findAll())ページネーション版
レスポンスサイズ無制限ページサイズで制御
ソートなし指定可能（デフォルト付き）
メモリ使用量全件ロードページ分のみ
本番適用❌ 危険✅ 推奨

2Repository: PagingAndSortingRepositoryを継承

ProductRepository.java
public interface ProductRepository
        extends CrudRepository<Product, Long>, PagingAndSortingRepository<Product, Long> {
}
💡 ポイント

PagingAndSortingRepositoryを継承すると、ページ指定を受け取るfindAllが使えるようになる。

PagingAndSortingRepository
Page<T> findAll(Pageable pageable);

3Controller: ページネーション・ソート付きの一覧取得

ProductController.java
@GetMapping
private ResponseEntity<List<Product>> findAll(Pageable pageable) {
   Page<Product> page = productRepository.findAll(
           PageRequest.of(
                   pageable.getPageNumber(),
                   pageable.getPageSize(),
                   pageable.getSortOr(Sort.by(Sort.Direction.DESC, "createdAt"))));
   return ResponseEntity.ok(page.getContent());
}

処理は次の3段階。それぞれを下の「🔍 詳しく」で順に説明する。

  1. 1リクエストをPageableで受け取る?page=1&size=20&sort=price,asc → Pageable pageable
  2. 2PageRequest.of()で作り直してfindAllに渡すソートの指定がなければ新着順に差し替える
  3. 3返ってきたPageからデータ本体だけ返すpage.getContent()
🔍 詳しく: ① リクエストをPageableで受け取る

1クエリパラメータとPageableの対応

Pageableは、ページネーション情報（ページ番号・件数・ソート条件）をひとまとめに表すSpring Dataのインターフェース。コントローラの引数にPageable pageableと書くだけで、Spring MVCがクエリパラメータから自動的に組み立てる。

たとえば次のリクエストでは、色を付けた3つのパラメータがそれぞれPageableのメソッドに対応する。

GET /products?page=1&size=20&sort=price,asc
page=1 → getPageNumber()戻り値: 1 2ページ目（0始まりなので1は2ページ目）
size=20 → getPageSize()戻り値: 20 1ページに20件ずつ
sort=price,asc → getSortOr(...)戻り値: price: ASC 価格の安い順（指定がなければgetSortOrに渡したデフォルト＝新着順）
📖 つまり

商品を価格の安い順に並べ、20件ずつ区切ったときの2ページ目＝21〜40件目を取得する。

パラメータを省略したときは、次の値になる。

パラメータ省略したとき
page0（1ページ目）
size20
sort並び順なし（このコードではgetSortOrで新着順にする）

2@RequestParamは書かなくていい

Pageableは@RequestParamとは別の仕組みで値が詰められる。

仕組み読み取るもの
@RequestParamクエリパラメータを1つ、引数に1対1で入れる（?name=Taro → String name）
PageableSpring Dataの専用リゾルバ（PageableHandlerMethodArgumentResolver）がpage・size・sortをまとめて読み、1つのオブジェクトに組み立てる

Spring BootではSpring Data Webの自動設定でこのリゾルバが最初から有効になっているので、引数にPageable pageableと書くだけでよい。

🚫 @RequestParamを付けるとエラーになる
NG
findAll(@RequestParam Pageable pageable)

pageableという名前のクエリパラメータを1つ探してPageable型に変換しようとする。そんなパラメータは送られてこないので、400 Bad Requestや型変換エラーになる。

3省略時の値を変える

@RequestParam(defaultValue = ...)の代わりに、@PageableDefaultで指定する。

findAll(@PageableDefault(size = 20, sort = "createdAt", direction = Sort.Direction.DESC) Pageable pageable)

アプリ全体で揃えたい場合はapplication.propertiesに書く。

application.properties
spring.data.web.pageable.default-page-size=20
spring.data.web.pageable.max-page-size=100
💡 ポイント

max-page-sizeを設定しておくと、?size=100000のように大きすぎる件数を指定されても上限で抑えられる。

🔍 詳しく: ② PageRequest.of()で作り直してfindAllに渡す

1作り直す理由: ソートだけ差し替えたい

Page<Product> page = productRepository.findAll(
        PageRequest.of(
                pageable.getPageNumber(),   // 1
                pageable.getPageSize(),     // 20
                pageable.getSortOr(Sort.by(Sort.Direction.DESC, "createdAt"))));  // price: ASC

pageableから3つの値を取り出し、それを材料にPageRequestを作り直している。ページ番号と件数は受け取った値をそのまま使い、ソートだけを差し替える。

  • pageableをそのまま渡すと、sortが指定されなかったときは「並び順なし」になる
  • getSortOr(デフォルト)は、指定があればそのソート、なければ引数のデフォルト（ここでは登録日時の新しい順＝新着順）を返す
💡 ソートのデフォルトは自分で決める

pageやsizeと違い、「どの項目で並べるか」はエンティティごとに違うので、Springはソートのデフォルトを用意しない。明示的に指定する。

2PageableとPageRequestの関係

findAll()の引数の型はPageRequestではなくPageable。PageRequestはPageableを実装したクラスなので、そのまま渡せる。

型種類作り方
PageableインターフェースControllerの引数に書くとSpringが組み立てる
PageRequestPageableの実装クラスPageRequest.of()で自分で作る

PageRequest.of()はPageRequestを作るためのstaticメソッド（ファクトリメソッド）。コンストラクタはprotectedなので、new PageRequest(...)ではなくof()を使う。

PageRequest.of(1, 20);                                // ページ番号, 件数
PageRequest.of(1, 20, Sort.by("price"));              // + ソート
PageRequest.of(1, 20, Sort.Direction.ASC, "price");   // + 方向とフィールド名

3作り直さずに findAll(pageable) とも書ける

引数の型がPageableなので、Controllerが受け取ったpageableをそのまま渡すこともできる。

productRepository.findAll(pageable);

デフォルトのソートを@PageableDefaultで決めておけば（上の「① リクエストをPageableで受け取る」の「3. 省略時の値を変える」）、PageRequest.of()で作り直す必要はない。

🔍 詳しく: ③ 返ってきたPageからデータ本体だけ返す

以下、商品が全部で95件あり、?page=1&size=20&sort=price,ascでリクエストされた場合で説明する。

1findAllの裏で動くSQL

リポジトリは裏で次の2本のSQLを実行する。

-- データ本体：価格の安い順に並べて、20件飛ばして20件取る
SELECT * FROM product ORDER BY price ASC LIMIT 20 OFFSET 20;

-- 総件数：全部で何件あるか数える
SELECT COUNT(*) FROM product;

2Page<Product>の中身

この2本の結果をまとめた箱がPage<Product>。中身はPage型のメソッドで取り出す。コードではfindAll()の戻り値を変数pageで受けているので、page.getContent()のように呼ぶ。

Pageのメソッド値意味
page.getContent()商品20件のリストデータ本体（21〜40件目）
page.getTotalElements()95総件数
page.getTotalPages()5総ページ数（95 ÷ 20 を切り上げ）
page.getNumber()1今が何ページ目か（0始まり）
page.hasNext()true次のページがあるか

page.getContent()以外の総件数やページ数をメタ情報と呼ぶ。画面で「全95件」「1 2 3 4 5」のようなページ送りを作るときに使う。

3getContent()でデータ本体だけ返す

このコードはreturn ResponseEntity.ok(page.getContent());で、Pageオブジェクト全体ではなくデータのリスト部分だけを返す。レスポンスの形をシンプルに保てる。

⚠️ メタ情報はクライアントに届かない

クライアントに返るのは商品20件のリストだけで、総件数やページ数は捨てている。ページ送りの画面を作るなら、メタ情報も返す必要がある。
