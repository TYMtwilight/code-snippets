このセッション（または直前のやり取り）で学んだ知識を、`templates/snippets-template.html` のデザイン・構成に沿ったスニペットファイルとして作成してください。

対象トピック（指定があれば）: $ARGUMENTS

## 手順

1. **対象範囲の特定**
   - `$ARGUMENTS` が指定されていればそのトピックに関する内容を会話履歴から抽出する。
   - 指定がなければ、直近の会話で説明・学習したトピックのうち、スニペット化する価値がありそうなものを判断する。複数トピックがあり得る場合や、対象が曖昧な場合は、作成前に一度ユーザーに確認する。

2. **テンプレートの読み込み**
   - `templates/snippets-template.html` を読み込み、その構造・スタイル（hero ヘッダー、各 section のクラス名・アイコン、タグのマークアップなど）をそのまま踏襲する。テンプレート自体は変更しない。

3. **保存先フォルダの決定**
   - リポジトリ直下の既存カテゴリフォルダ（例: `spring/`, `java/`, `react/`, `javascript/`, `typescript/`, `nextjs/`, `security/`, `devops/`, `database/`, `tools/`, `thinking-method/`）を確認し、内容に最も近いフォルダを選ぶ。
   - 既存のサブフォルダ構成（例: `spring/controller/`, `spring/test/`, `react/hooks/` など）も踏まえ、適切な階層に配置する。
   - 既存フォルダのどれにも当てはまらない新しいカテゴリだと判断した場合は、新規フォルダを作る前にユーザーに確認する。

4. **ファイル名**
   - 内容を表す英語 kebab-case で命名する（例: `use-callback-dependencies.html`）。既存ファイル名の命名傾向に合わせる。

5. **内容の作成**
   - `snippets-template.html` の各セクションを、実際に学んだ内容で埋める。
     - 概要: 1〜2行で目的・要点
     - 使用場面: 具体的なシチュエーション
     - コード: 会話中に出てきた実際のコード例（なければ代表的な最小例を作る）
     - 説明: コードの重要なポイント、なぜそうするのかを中心に
     - 参考: 会話中で言及された公式ドキュメント等のURL（なければ省略可、URLを捏造しない）
     - 関連スニペット: リポジトリ内の既存ファイルを `Grep`/`Glob` で検索し、関連が強いものを相対リンクでつなぐ。見つからなければ省略する。
     - タグ: 技術要素を表す3〜6個程度
   - 作成日・更新日は今日の日付を使う。
   - プレースホルダー（`[スニペット名]`、`URL` など）や `class="placeholder"` は実際の内容に置き換え、使わなかった要素（`placeholder` クラスなど）は削除する。

6. **ファイル作成**
   - 決定したパスに新しい HTML ファイルを作成する。git commit は行わない（ユーザーが明示的に指示するまで待つ）。

7. **完了報告**
   - 作成したファイルパスと、内容判断で迷った点（カテゴリ・関連スニペットなど）があれば簡潔に報告する。
